# Contrat — API HTTP `btmuxd` v0.2.0 (périmètre « appairages »)

> **Statut : validé au GATE 2 v0.2.0 (2026-10-23 17:12)** — contrat de référence pour LOT-2 « appairages + Web UI » (#20 #21 #16). Serveur aiohttp ; mise à jour en direct par SSE avec repli polling.

> Contract-first (#21). Serveur : `aiohttp` (asyncio natif, pas de pydantic côté serveur — décision GATE 2 du 2026-10-23). Écoute `api.listen` (défaut `0.0.0.0:8088`, LAN seul). **Auth** : `Authorization: Bearer <jeton>`,
> jeton lu dans `api.token_file` (`/etc/btmux/token`, mode 0600, généré à l'installation s'il manque). `GET /` et `/static/*`
> (Web UI) sont publics, tout `/api/*` exige le jeton (401 sinon). Réponses JSON UTF-8 ; erreurs `{ "error": "<code>", "message": "<texte>" }`.

| Méthode | Route | Rôle | Réponse |
|---------|-------|------|---------|
| GET | `/api/health` | vivacité (public) | 200 `{ "version": "0.2.0.0", "adapters": 2 }` |
| GET | `/api/state` | adaptateurs + appareils connus (modèles `models.md`) | 200 `State` |
| POST | `/api/pairing` | ouvrir la fenêtre d'appairage `{ "adapter": "sources"\|"headsets", "duration": 60 }` (1..300 s ; `discoverable+pairable` sur l'adaptateur du rôle ; pour `headsets` lance aussi `StartDiscovery`) | 202 `PairingWindow` ; 409 si une fenêtre est déjà ouverte |
| DELETE | `/api/pairing` | fermer la fenêtre → événement `pairing` `{open:false, reason:"closed"}` ; expiration → `reason:"expired"` ; réouverture sur l'autre adaptateur après 409 évitée (une seule fenêtre) | 204 (204 aussi si déjà fermée) |
| GET | `/api/discovered` | appareils vus pendant une fenêtre `headsets` (non appairés) | 200 `Discovered[]` |
| POST | `/api/devices/{mac}/pair` | appairage **initié par le Pi** (casques) : pair + trust + connect sur l'adaptateur `headsets` | 202 ; 404 si non découvert ; 409 si fenêtre fermée |
| POST | `/api/devices/{mac}/connect` | `Device1.Connect` (Pi initiateur) | 202 ; 404 inconnu |
| POST | `/api/devices/{mac}/disconnect` | `Device1.Disconnect` | 202 |
| POST | `/api/devices/{mac}/forget` | `Adapter1.RemoveDevice` (oubli des deux côtés à faire par l'utilisateur sur la source) → événement **`device.removed`** `{mac, adapter}`, puis `device` placeholder si l'appareil est dans la config | 204 |
| PATCH | `/api/devices/{mac}` | `{ "trusted": bool }` et/ou `{ "alias": "pc-pro" }` (alias btmux, pas l'alias BlueZ) | 200 `Device` |
| GET | `/api/events` | flux **SSE** (`text/event-stream`) : `adapter`, `device`, `pairing`, `discovered` avec le modèle complet en `data` ; `retry: 3000` | 200 |
| | | **Client** : `/api/events` exige le Bearer comme tout `/api/*` ; `EventSource` ne pouvant pas envoyer d'en-tête, la Web UI lit le flux par `fetch` streaming (`ReadableStream`) avec l'en-tête `Authorization`, gère elle-même `retry` et renvoie `Last-Event-ID` à la reconnexion ; le serveur honore `Last-Event-ID` (rejoue les événements manqués dans la limite d'un tampon de 100, sinon envoie un événement `state` complet). Ajouté le 2026-10-24 (#16/#21). | |

| GET | `/api/route` | **#29** — route courante (source unique vers tous les casques connectés) | 200 `Route` |
| POST | `/api/route` | **#29** — **choix manuel** `RouteSet` : liens basculés (break-before-make, FL/FR en un envoi), « pause » AVRCP à la source quittée (puis coupure A2DP si ignorée, cf. config-schema § Routage), `mode:"manual"`, `reason:"manual"` ; **tenu jusqu'au prochain démarrage d'une source** (n'importe laquelle, A2DP ou HFP), puis l'automatique reprend ; aucune commande « lecture » envoyée à la source choisie. Ordre de contrôle : 400 `invalid_body` → 409 `routing_disabled` (`routing.auto:false`) → 404 `unknown_source` (MAC/alias inconnu, pas `kind: source`, non connecté, ou pas sur le rôle `sources`) → no-op (source déjà routée : 200 inchangé, aucune pause) → 503 `pipewire_unavailable` | 200 `Route` (après liens `active`, ≤ 2 s) |
| DELETE | `/api/route` | **#29** — retour à l'automatique : la source **encore `streaming`** la plus récemment démarrée prend la route, sinon la route courante est conservée ; `mode:"auto"`, `reason:"auto_resumed"` (200 aussi si déjà en auto) ; 409 `routing_disabled` | 200 `Route` |
| GET | `/api/controllers` | **#23** — tous les contrôleurs BlueZ détectés (configurés ou non) + `Roles` : `{ "controllers": Controller[], "roles": Roles }` | 200 |
| PUT | `/api/controllers/roles` | **#23** — affectation **atomique** des deux rôles `RoleChange` (`null` = rôle libéré ; permutation en un appel ; tout contrôleur présent est affectable, UART compris). **Corps strict** : `sources` et `headsets` obligatoires (MAC ou `null`), `confirm` optionnel (booléen) ; toute autre clé (ex. `force`) → 400 `invalid_body`. Refus 400 : `invalid_body` (clé inconnue/manquante), `invalid_confirm`, `invalid_mac`, `unknown_controller` (MAC inconnue ou `present:false`), `same_controller` (même MAC pour les deux rôles) ; 409 `pairing_open` (fermer la fenêtre d'abord), 409 `devices_connected` (`details: [{mac, alias, name, adapter}]` des appareils connectés sur les rôles modifiés) sauf `confirm:true` → le daemon déconnecte d'abord, 409 `change_pending` ; **affectation identique à l'affectation courante → 200 `Roles` inchangé (no-op, aucun redémarrage), évalué avant tout 409 d'état (un no-op réussit même fenêtre ouverte)** ; ordre de contrôle : 400 (validation) → no-op 200 → 409 `change_pending` → 409 `pairing_open` → 409 `devices_connected` ; **502 `disconnect_failed`** (`confirm:true`) si un appareil connecté ne peut pas être déconnecté, ne confirme pas `Connected=false` sous 5 s (déconnexions **en parallèle** : attente ≲ 5 s au total ; un appareil déjà déconnecté/`NotConnected` compte comme succès), ou **se reconnecte** sur un rôle modifié avant l'écriture (`details: [{mac, alias, name, adapter}]` des appareils encore connectés) : **rien n'est écrit**, `Roles` inchangé, `pending:false`, pas de redémarrage — réessayer ; les contrôles 409 `change_pending` / `pairing_open` sont **rejoués après les déconnexions** (l'état a pu changer pendant l'attente) ; **500 `state_write_failed`** si l'écriture du fichier d'état échoue (droits, disque) : `Roles` inchangé, `pending:false` (les appareils ont déjà été déconnectés : les déconnexions **précèdent** l'écriture depuis la révision S3 du 2026-10-26, le bus devant être ouvert) ; succès : appareils déconnectés et confirmés si `confirm`, état écrit atomiquement, **puis redémarrage du service** (D3 — voir config-schema § Affectation) | 202 `Roles` (`pending:true, restart_expected:true`) + événement `roles`, puis coupure de l'API (≈ 15–20 s) ; au retour, `state` complet. 200 `Roles` si no-op ; 502 `disconnect_failed` ou 500 `state_write_failed` : rien d'écrit, pas de redémarrage |
| | | **Contrôleurs sans rôle** : à chaque démarrage, hotplug et changement de rôle, le daemon force `Pairable=false`, `Discoverable=false` sur **tous** les contrôleurs sans rôle (y compris le Bluetooth interne) ; `btmux-adapters.sh` fait de même en root (classe/alias non touchés). | |

Codes : 400 (validation), 401 (jeton), 404 (`unknown_source` #29), 409 (état : `pairing_open`, `devices_connected`, `change_pending`, `role_unassigned`, `routing_disabled` #29), 500 `state_write_failed` (#23, fichier d'état non écrit : rien n'est appliqué), 502 (erreur BlueZ, message D-Bus en `message` ; `disconnect_failed` #23 avec `details`), 503 (BlueZ indisponible ; `pipewire_unavailable` #29 : session PipeWire injoignable).
`role_unassigned` (#23) : `POST /api/pairing` et `/api/devices/{mac}/pair|connect` répondent 409 quand le rôle visé n'a pas de contrôleur affecté/présent.
`change_pending` : toute écriture (`POST` **et `DELETE`** `/api/pairing`, `/api/devices/*` dont `PATCH`, `/api/controllers/roles`) répond 409 entre l'acceptation d'un changement de rôles et l'arrêt du service ; les lectures (`GET`, `/api/events`) restent servies.
Erreurs : le champ optionnel `details` (tableau) complète `{error, message}` quand le code le prévoit (`devices_connected`, `disconnect_failed`) ; absent sinon.

**CLI `btmuxctl` (#23)** : `btmuxctl controllers` (JSON de `GET /api/controllers`) ; `btmuxctl roles set --sources <MAC|none> --headsets <MAC|none> [--confirm]`
(`none` = `null` ; `PUT /api/controllers/roles`, JSON de la réponse ; code 1 sur erreur API avec `error: message` et, si présent, `details` une ligne par appareil sur stderr).
**CLI `btmuxctl` (#29)** : `btmuxctl route` (JSON de `GET /api/route`) ; `btmuxctl route set <MAC|alias>` (`POST`) ; `btmuxctl route auto` (`DELETE`) ;
codes 0 succès, 1 erreur API (`error: message` sur stderr) ou API injoignable, comme les commandes existantes.
Limites v0.2.0 : routage limité à #29/#30 (une source vers tous les casques, pas de groupes/poids/mixage), pas de volume, pas de contrôle d'appel ; une seule fenêtre d'appairage à la fois ; les appairages
**entrants** (sources) sont acceptés automatiquement pendant la fenêtre `sources` (agent NoInputNoOutput), refusés hors fenêtre.
